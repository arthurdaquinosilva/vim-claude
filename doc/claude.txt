1. REQUIREMENTS                                           *claude-requirements*

- Vim 9.1.0120+ with |+job|, |+channel|, |+timers|, |+popupwin| and
  |+textprop| (|getregion()| is used). Run |:ClaudeHealth| to check.
  Neovim and Windows are not supported.
- The Claude Code CLI (`claude`) on your $PATH, already logged in. The
  plugin drives `claude -p` in stream-json mode, so it uses your existing
  subscription or API key and runs Claude Code's tools in Vim's |getcwd()|.

2. CHAT PANEL                                                     *claude-chat*

|:ClaudeToggle| (<Leader>cc) opens a panel on the right: the transcript on
top and a small input box below.

The transcript is an ordinary read-only buffer, so all of Vim works in it:
scroll, search with |/|, yank, |gf| on file names, fold a message with |zc|.
While Claude is streaming, a window that is scrolled to the bottom follows
the output; a window you scrolled back stays where you put it.

The input box starts one line tall and grows as you type. It sits between
two rules; the top one shows what Claude is doing while it works. Below,
file Claude will be told you are looking at, and the model and permission
mode (or how to stop Claude while it is busy).

Slash commands: type `/` at the start of the message and a menu lists every
command the CLI reported (built-ins, custom commands from `.claude/commands`
and `~/.claude/commands`, and skills), with their descriptions. Commands are
sent exactly as typed, without the editor context. The plugin handles these
itself, since the CLI cannot without a terminal:

  /clear /new        new conversation        |:ClaudeNew|
  /model [name]      choose the model        |:ClaudeModel|
  /permissions /mode choose the permission mode |:ClaudeMode|
  /resume            reopen a conversation   |:ClaudeResume|
  /help              list the commands
  /exit /quit        close the panel

Others, such as `/compact` and `/context`, run in the CLI and show their
result in the transcript. A command the CLI does not know is refused and left
in the input; start the message with a space to send it as plain text.

Input box:
  <CR>           send (insert and normal mode); picks the item if the
                 @file menu is open
  <Tab>          next item in the @file menu
  <C-j>          new line (also <S-CR> where the terminal supports it)
  @              fuzzy-complete a project file or directory (git ls-files)
  <C-p> <C-n>    previous / next sent message
  <C-r>          search earlier messages (type, <C-r>/<C-n>/<C-p> to move,
                 <CR> to take, <Esc> to cancel)
  <C-c>          stop Claude
  q              close the panel (normal mode)

Transcript:
  i a o <CR>     jump to the input box
  ]] [[          next / previous message
  gy             yank the code block under the cursor (also to "+)
  {Visual}<CR>   put the selected part of a reply in the input box (as a
                 quote, or a code block if it is code) to ask about it
  <C-c>          stop Claude
  q              close the panel

Each tool call is followed by its result: edits as a numbered diff with a
line of context, commands with the first lines of output (the rest is
counted), reads and searches with a count, todo lists as a checklist. Tune
with |g:claude_tool_details| and |g:claude_tool_lines|.

The statusline shows a spinner and what Claude is doing (thinking, using a
tool), the model, how full the context window is (ctx 12%), and the
permission mode. A warning appears when the context is 85% full. Each reply ends with its duration.

Shell commands: a message that starts with `!` runs in your shell, in the
conversation's directory, instead of going to Claude: `!git status`. The
output (stderr included) appears under it, and Claude is told what you ran and
what it printed together with your next message. One command runs at a time,
messages sent meanwhile wait for it, and it is stopped after
|g:claude_shell_timeout| seconds. Turn this off with |g:claude_shell_mode|.

Images: `@path/to/pic.png` (also jpg, gif, webp; up to 5 MB) in a message
attaches the image so Claude can look at it. A file that does not exist is left
as plain text. Needs the `base64` command.

Rewind: |:ClaudeRewind| (<Leader>cu, or `/rewind`) lists the messages you sent
in this session. Pick one and the plugin asks the CLI which files changed
since, shows them with the lines added and removed, and restores them when you
confirm. Only files are restored; the conversation stays as it is. The CLI
keeps the snapshots (|g:claude_checkpoints|).

Type ahead: pressing <CR> while Claude is still working queues the message
(shown as `⧗ Queued`, with a count in the info line). Queued messages are
sent in order, each as its own message, as soon as Claude finishes; <C-c>
stops the current reply and the queue carries on. |:ClaudeUnqueue| drops
them.

History is saved per project (under |g:claude_history_dir|) and loaded again
the next time you work in that directory.

A conversation works in the directory it started in until |:ClaudeNew|: a
|:cd| (or 'autochdir') in between does not move Claude to another project.
|:ClaudeContinue| reopens the latest conversation of the current directory;
|:ClaudeFork| makes the next message continue in a new session that starts
with everything said so far, leaving the original untouched.

The conversation is one Claude Code session; messages share context until
|:ClaudeNew|. Earlier sessions for the current directory can be reopened with
|:ClaudeResume|.

3. SELECTIONS AND CONTEXT                                      *claude-context*

Explain: select lines and press <Leader>ce (or `:'<,'>ClaudeExplain`). The
code is sent with its file name and line numbers, and shown in the transcript
so you can see what was asked.

Ask about a selection: `:'<,'>Claude is this thread safe?`

Add to chat: <Leader>ca (or `:'<,'>ClaudeAdd`) puts a mention such as
`@src/app.py#L10-24` into the input box. When the message is sent, the
lines are attached from the buffer, so unsaved changes are included.
Without a range it mentions the whole file (`@src/app.py`), which Claude
reads itself.

Each message also tells Claude which file and line you were on last
(disable with |g:claude_include_context|).

==============================================================================
4. INLINE EDIT                                                    *claude-edit*

Select lines and press <Leader>ci (or `:'<,'>ClaudeEdit add error handling`).
Without an instruction you are prompted for one. Claude rewrites only the
selection; the result opens in a new tab as a diff, your buffer on the left
and the proposal on the right:

  ga             accept the whole proposal (one undo step: |u| reverts it)
  gr  q          reject
  do  dp         take or put single hunks with normal |diff| commands

You can also edit the proposal buffer before accepting.
If the buffer changes while Claude is working, the proposal is discarded.

5. PERMISSIONS                                            *claude-permissions*

Claude Code asks before editing files or running commands. The request
reaches Vim while Claude waits, and a popup shows exactly what it wants to do:
the lines it would change as a diff, the command it would run, or the other
arguments. Answer with one key:

  y  1           allow this call
  a  2           allow it for the rest of the session (for Bash: that exact
                 command); Claude is not asked again, nothing restarts
  e  3           accept all edits (switch to acceptEdits mode); only offered
                 for Edit and Write
  n  Esc         deny; Claude is told and carries on without it

Several requests at once are shown one after the other. <C-c> in the panel
(or |:ClaudeStop|) while a popup is open denies the waiting requests and
interrupts. The starting mode is |g:claude_permission_mode|; switch with
|:ClaudeMode|. Files Claude changed are reloaded when the reply ends.

|g:claude_permission_prompt| = 'retry' restores the older behavior for CLIs
that cannot ask: Claude is denied, the popup comes after the reply, and the
plugin asks Claude to retry once you allow.

Plan mode: <S-Tab> in the input box cycles default, acceptEdits and plan. When
Claude finishes planning, a popup shows the plan (scroll with j k <C-d> <C-u>):
`y` approves and returns to the previous mode, `a` approves and auto-accepts
edits, `n` asks Claude to keep planning.

Questions: when Claude asks you to choose (AskUserQuestion), a popup lists the
options. Press the number to answer, `o` to type your own answer, <Esc> to
skip. With several choices allowed, numbers toggle and <CR> confirms.

Changing the model (|:ClaudeModel|) or the mode (|:ClaudeMode|) applies to the
running session immediately. Switching to bypassPermissions asks for
confirmation (|g:claude_confirm_bypass|).

Stopping: <C-c> asks Claude to interrupt the reply. The session and its
prompt cache stay alive, so the next message continues without a restart. If
Claude does not stop within three seconds the process is killed (the
conversation is resumed on the next message).

6. COMMANDS                                                   *claude-commands*

:Claude [text]               *:Claude*
    Open the panel, or send [text]. With a range: send the selection with
    [text] as the question, or add it to the input box if [text] is empty.
:ClaudeToggle                *:ClaudeToggle*   Show / hide the panel.
:ClaudeOpen  :ClaudeClose    *:ClaudeOpen* *:ClaudeClose*
:[range]ClaudeExplain        *:ClaudeExplain*  Explain range (default: file).
:[range]ClaudeAdd            *:ClaudeAdd*      Mention range in the input box.
:[range]ClaudeEdit [instr]   *:ClaudeEdit*     Inline edit with diff review.
:ClaudeAccept :ClaudeReject  *:ClaudeAccept* *:ClaudeReject*
:ClaudeEditCancel            *:ClaudeEditCancel*  Cancel a running edit.
:ClaudeRewind                *:ClaudeRewind*   Restore files to an earlier message.
:ClaudeStop                  *:ClaudeStop*     Interrupt the current reply.
:ClaudeUnqueue               *:ClaudeUnqueue*  Drop messages waiting to be sent.
:ClaudeHealth                *:ClaudeHealth*   Check Vim, the CLI and the login.
:ClaudeNew                   *:ClaudeNew*      Start a new conversation.
:ClaudeResume                *:ClaudeResume*   Reopen an earlier conversation.
:ClaudeContinue              *:ClaudeContinue* Reopen the latest conversation here.
:ClaudeFork                  *:ClaudeFork*     Branch into a new session.
:ClaudeModel [name]          *:ClaudeModel*    opus, sonnet, haiku, default,
                                               or any model id.
:ClaudeMode [mode]           *:ClaudeMode*     default, acceptEdits, plan,
                                               bypassPermissions.

7. MAPPINGS                                                   *claude-mappings*

Normal mode               Visual mode
  <Leader>cc  toggle        <Leader>cc  add selection to input
  <Leader>ce  explain file  <Leader>ce  explain selection
  <Leader>ca  add file      <Leader>ca  add selection to input
  <Leader>ci  edit line     <Leader>ci  edit selection
  <Leader>cn  new chat
  <Leader>cr  resume
  <Leader>cm  pick model
  <Leader>cp  pick permission mode
  <Leader>cu  rewind files

Change the <Leader>c prefix with |g:claude_map_prefix|, e.g. >
    let g:claude_map_prefix = '<Leader>i'
<Set |g:claude_no_mappings| to define your own.

8. OPTIONS                                                     *claude-options*

*g:claude_cmd*              CLI to run: string or list.     Default: 'claude'
*g:claude_model*            Model alias or id.              Default: CLI default
*g:claude_edit_model*       Model for |:ClaudeEdit|.        Default: g:claude_model
*g:claude_permission_mode*  Starting mode.                  Default: 'default'
*g:claude_permission_prompt* 'host': the CLI asks Vim and    Default: 'host'
                            waits for the answer; 'retry':
                            ask after the reply, then retry.
*g:claude_position*         'right', 'left' or 'bottom'.    Default: 'right'
*g:claude_width*            Panel width: columns, or a      Default: 0.5
                            fraction of the screen (0.5 =
                            half; kept on resize).
*g:claude_height*           Panel height for 'bottom'.      Default: 18
*g:claude_input_height*     Minimum input box height; it    Default: 1
                            grows with what you type.
*g:claude_input_border*     Draw a rule under the input     Default: v:true
                            box, above the info line.
*g:claude_input_max_height* Maximum input box height.       Default: 12
*g:claude_input_tint*       Give the input box a slightly   Default: v:false
                            different background than Normal.
*g:claude_include_context*  Tell Claude the current file.   Default: v:true
*g:claude_fence_syntax*     Highlight ```lang blocks with   Default: v:true
                            that language's syntax.
*g:claude_format_tables*    Redraw Markdown tables in       Default: v:true
                            replies as aligned box tables.
*g:claude_tool_details*     Show what tool calls did.       Default: v:true
*g:claude_tool_lines*       Most lines shown under a call.  Default: 12
*g:claude_confirm_bypass*   Ask before bypassPermissions.   Default: v:true
*g:claude_history*          Keep input history on disk.     Default: v:true
*g:claude_history_dir*      Where it is kept.               Default: ~/.local/state/vim-claude
*g:claude_history_search_key* Key for history search.       Default: '<C-r>'
*g:claude_queue_limit*      Most messages that can wait.    Default: 10
*g:claude_checkpoints*      Let |:ClaudeRewind| restore     Default: v:true
                            files (the CLI snapshots them).
*g:claude_shell_mode*       `!command` runs in your shell.  Default: v:true
*g:claude_shell_timeout*    Seconds before it is stopped.   Default: 120
*g:claude_shell_lines*      Output lines shown for it.      Default: 25
*g:claude_show_cost*        Show API cost in reply footers. Default: v:false
*g:claude_extra_args*       Extra CLI arguments (list).     Default: []
*g:claude_debug_log*        File to append the raw CLI     Default: ''
                            events to (for bug reports).
*g:claude_map_prefix*       Prefix for default mappings.    Default: '<Leader>c'
*g:claude_no_mappings*      Skip default mappings.          Default: v:false

Highlight groups (override after your colorscheme to restyle):
  ClaudeInput        input box background (default: same as Normal)
  ClaudePromptSign   the ❯ prompt          ClaudePlaceholder  hint text
  ClaudeRule         rule and info line    ClaudeKey          ctrl-c hint
  ClaudeBusy         spinner and status    ClaudeChip         context file
  ClaudeYou          ❯ You: label          ClaudeAssistant    ✻ Claude: label
  ClaudeUserText     your messages         ClaudeTime         message times

Fenced code blocks (```js, ```python, ```tsx, ```bash, ...) are highlighted
with that language's own syntax, loaded the first time it appears. Common
short tags are understood (js, ts, tsx, py, sh, yml, rb, rs, ...); any other
tag works when Vim has a syntax file of that name. Disable this with
|g:claude_fence_syntax|.
